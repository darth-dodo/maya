# Factory lessons

Rules the factory learned the hard way, grouped by station. Each one cites the PR or Issue it came from.
`factory:build` reads this file at step 4. Change it only through a `factory:improve` PR. Keep it under 40 rules.

## Plan
- Give every PR an Issue with an estimate, linked to its spec PR, even small follow-ups and spec-only PRs, because a change without one is invisible to `next-task` and leaves blank retro cells: the dry run's spec PR had no Issue until one was added by hand, and #149 and #180 shipped fixes with no Issue; file the follow-up bug Issue for a deferred finding before merge, because #191's F4 and F5 waited until #192 was filed by hand (#12, #30, #140, #149, #180, #191).
- When a design session or grill changes a rule, update every doc that states it in the same PR, because #27 left the old voice fallback in three other files until review (#27).
- Split a redesign into one OpenSpec change per build Issue and give each its own CSS scope (`.home-tide`), because #131's split let #135 and #136 build in parallel on `app.css` and merge 24 s apart with no conflict (#131).
- Score an experiment only with a metric its change can move, and only over the PRs it guards with known values, because E3's hourly text Question was scored on escaped defects that were all phone-only bugs it could never catch (#63, #74), and E4's batch rows include PRs that touch no phone file while its guarded rows (#135, #136) stay blank until the phone checks run (#144).

## Build
- Use the Supabase session pooler URI (`aws-0-eu-west-1.pooler.supabase.com:5432`) as `DATABASE_URL`, never the project API URL (`Ecto.InvalidURLError`), the direct host (IPv6 only, `nxdomain`) or port 6543 (transaction pooler, breaks prepared statements) (#4, #5, #7).
- Generate `SECRET_KEY_BASE` with `mix phx.gen.secret` and check it is 64+ bytes, because a short key passes `/health` but 500s every session page, so a broken deploy goes live (#8).
- Read env vars only in `config/runtime.exs` and list them in the FACTORY.md secrets table, never in controllers, because reviewers block direct `System.get_env` in `lib/` (#22).
- Deny overlapping plugin skills with `Skill(skill:<name>)` rules in `.claude/settings.json`, because `skillOverrides` does nothing for plugin skills (#9).
- In a worktree, run the DB with `docker compose -p maya up -d --wait db`, because the `-p maya` reuses the main checkout's container instead of starting a second one on the same port (#21, #22).
- Run `mix format` before the first `factory:test`, and select by DOM id in tests (`#tagline`), not raw HTML matches, per AGENTS.md, because the dry run's only red gate was format and its main review finding was raw HTML matching (#16).
- When a branch conflicts with `main`, `git merge origin/main` and keep both sides, because force push is denied and rebasing a pushed branch needs it (#21). Merge main into every open builder branch right after a convention PR merges, and before the first push when other PRs land the same hour, because #25 conflicted on CLAUDE.md after #23 landed and #153 pushed twice for a conflict; rerun the review after that merge, because #182's merge of #180 broke `follow/2` (#25, #153, #182).
- Run a format or API spike with a real key before writing the decode path, and run every risky integration task (tools plus `response_format`, a tool choice, a stage budget) on the real model before merge, asking Abhishek to run it when agents have no key, because #48 assumed int16 PCM and needed a float32 fix, #179 merged without its task 1.1 and failed on the phone, and #177's stubbed probes passed while the real model used `set_team` for one level change (#48, #177, #179).
- Run one plain command per tool call and keep temp files inside the worktree, because compound commands and paths outside it were the builders' denied calls (#47, #48).
- Send provider defaults explicitly when the product needs one value (STT language `en`), because Voxtral guessed Hindi per clip on English Questions until #59 sent the language (#59).
- Never change layout under an active touch (no resize, reflow or LiveView patch of the pressed element while a finger is down), and end a hold from document-level `pointerup` and `pointercancel`, because #74 shrank the trainer card under the finger and broke hold to talk on iPhone, and #165's hold never ended when the browser took the touch (#74, #76, #165).
- Make tool-driven writes idempotent, keyed to the tool call (one Event per tool call), not to a time window, because #86 applied a repeated catch twice and filled the Team with duplicates, and #162's 2 minute content window can still drop a real second catch (#86, #116, #162).
- Put every browser storage access behind one helper that survives a blocked or throwing `localStorage`, because blocked storage broke the theme toggle (#155) and the LiveView connect on `/talk` (#161) in two separate places (#150, #155, #161).
- Let Maya state only tool results she received, never the result of a tool she did not call, because Answers claimed refusals from tools that never ran (#55, #118), and back each claim with a confirmed write from the tool result, never any write that ran, because a refused `set_setting` backed "Humor set to 100" from #190 until #203 (#190, #203); tune the honesty check from real phone transcripts and Render log lines, not guessed word lists, because #179's check rejected real Team changes, tool Questions and unknown cited ids until #184 (#179, #184).
- Run `factory:review` and grep the tests for any list you extend (agent tools, ids) before the first push, because #128 pushed twice: CI went red on a pinned tool list and review found a fail-open cap only after the push (#128).
- Never push to a branch whose PR already merged; start a new branch from `origin/main`, and mark a PR draft while a blocking fix is in flight, because commits pushed to #54's merged branch were lost until #71 carried them, and #148 merged during the push of its privacy fix, which became #149 (#71, #148, #149).
- Log the reason of every failed stage (an atom, status or exception message, never transcripts, Answers or keys), because #55's Conversation logged nothing and its root cause needed a Render trace (#60).
- Answer an infrastructure flake with the tool's documented fallback setting, not a retry, because #42's Hex outage maps to setup-beam's `hexpm-mirrors` and #52 fixed it in one line (#52).

## Verify
- Run every gate CI runs on its own, locally, before the first push, and judge it by its exit code, never through `| tail` or `| grep`, because a pipe hides a red gate (#15), and with local Postgres hung #163's changed test first ran in CI and went red, #145's new Node 24 test step failed only in CI, and #138 shipped on CI reruns without its local repeat runs; `openspec validate --all --strict` is one of them, since CI does not run it and #165 and #177 added requirements over 500 characters; run any script a PR body hands to Abhishek once with macOS `/bin/bash` (3.2), because #199's board migration script needed a rewrite (#15, #138, #145, #163, #175, #177, #199).
- Tick a `tasks.md` box only after its own verification ran, because a ticked task with missing work became a blocking review finding (#22).
- Prove a new gate can fail (one red run, local or in CI, then green) and document how to satisfy it before trusting it, because a gate that never fails proves nothing (#22) and #129's phone gate had no route to a branch on the phone, so its first PR merged with it pending (#129).
- Make optional external reporters non-blocking and prove their failure path in CI before relying on them, because #53's Codecov upload failed without a token and CI stayed green as designed (#53).
- Check every press path or Talk layout change on a real phone before merge, with the largest real data (a full Team at 375 px), because #81's fresh mic per press cut the first words (#94) and #84's sticky card covered a third of the screen (#117), and only the phone showed either; `factory:review` lists a pending `Phone check:` line under Blocking, never only in the Checklist, because #130, #150, #165, #178, #181 and #182 among others merged with it pending, and #176's check on the phone is what proved its band; a spike is done only when its phone table is filled, because #200 merged its audio panel with the iPhone table pending (#81, #84, #176, #200, E4).
- Judge a fixed or sticky element with viewport screenshots at phone size, never full-page ones, because #154's full-page screenshot showed the pill over the Answer when it was not (#154).
- Give every `curl` in a workflow `--max-time`, because a hung request runs into `timeout-minutes`, ends as cancelled and skips `if: failure()` steps (#22).

## Review
- Check each Issue "done when" against the skill and doc files too, not only the code, because review found a skill that never named the new checks (#22).
- Show visual and copy options (screenshots, a page, 2 or 3 taglines or summaries) before review, because the welcome page changed twice after review (#24), #54 took three post-review commits to settle its lines and #158 pushed again when option D was chosen (#24, #54, #158).
- Fix cheap non-blocking findings (dead CSS, stale counts, a missing citation) and any finding that names a failure path (throws, blocked, crashes, a refused write that still backs a claim) or a spoiler (a place, trainer or item reachable later than its badges say) in one commit before asking for merge, because #136 merged with all 5 findings untouched, #142's missing citation is still on `main`, #150's blocked-storage finding became #155 and #161, #190's F3 became #192, and #198's F6 shipped Rhett's Makuhita at 0 badges until #201 (#136, #142, #150, #190, #198, #201).
- Post the `factory:review` comment on every PR, even a one-line config or release PR (#187 and #195 had none), and wait for it before the PR is merged, and never merge with a Blocking code finding open (push the fix first, or mark the PR draft), because #100, #160 and #178 merged with blockers open and each needed a follow-up PR (#180 for #178's lost member and LiveView crash), and #172's review landed after merge (#100, #160, #172, #178).

## Ship
- Add a changelog fragment `changelog.d/<branch-with-dashes>.md`, never a line in `CHANGELOG.md`, because a file every PR appends to made nearly every parallel PR conflict (#23).
- Run CI on the merge result of parallel PRs before the second one merges, and grep callers on the latest `origin/main` when changing a public function's arity, because #63 and #65 were each green and together broke main (#63, #65, #72).
- Run any check that waits for the deploy on a schedule, and make every check on the head commit finish fast and exit 0 unless the code is broken, because Render's `checksPass` waits on pending checks and refuses failed ones, so a push-triggered smoke check deadlocked it and blocked every deploy (#22, #28).
- Make the deploy step leave production able to run (migrate, then seed the data the app reads), never a manual import, because #55 shipped to an empty Progress table and every Answer failed until #60 seeded on deploy; commit the script that generates a data file in the same PR as the file, because #201's `access.json` came from an uncommitted walk and #204's rerun raised 3 rows (#55, #60, #201, #204).
- Check after each deploy that one real Question works against production data, not only that CI passed on fixtures, because #55 was green in CI and failed every Question in production; the hourly smoke Question does this (#55, E3).
- Cut a release only after its queued PRs merge, and pin the fold to a named `origin/main` SHA listing which open PRs land in the next version, because #33's changelog fragment missed v0.1.0 by 38 seconds (#33, #34) and #127 folded cleanly while #128 and #130 were still open (#127).
